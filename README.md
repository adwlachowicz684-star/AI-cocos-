## 一、核心理念

### 1.1 解耦 ≠ 可复用

这是三个容易混淆的概念：

- **解耦**：A 不依赖 B —— 是**手段**
- **可复用**：换个项目能直接搬走 —— 是你的**目标**

一个「解耦得很干净」的模块，依然可能完全不可复用：

```typescript
// 它不依赖任何东西（解耦了），但你做下一个游戏时一点用都没有
class EnemyPool {
    get(): Enemy { ... }   // ← 写死了「敌人」
}
```

可复用的版本是 `Pool<T>` —— **它不知道自己装的是什么**。

> **可复用 = 解耦 + 不依赖具体业务概念**

### 1.2 唯一的一句口诀

> **每当你的函数参数写了一个具体类型，问自己：我真正需要它的什么能力？**

```typescript
// ❌ 只能打敌人
function takeDamage(target: Enemy, dmg: number)

// ✅ 你要的其实是「它能被扣血」
function takeDamage(target: IDamageable, dmg: number)
```

### 1.3 什么不该复用

> **机制可以复用，内容不要复用。**

| 机制（复用） | 内容（不复用） |
|---|---|
| 伤害管线 | 骨王的横扫技能 |
| 行为树框架 | 骷髅兵的行为树配置 |
| 对象池、掉落表 | 55 件遗物的具体效果 |

**三次法则**：第一次直接写，第二次复制粘贴忍住，**第三次才抽象**。
只有见过三次你才知道真正的共性在哪——第二次就抽往往会抽错。

## 二、七条铁律

| # | 铁律 | 判据 |
|---|---|---|
| 1 | **零业务依赖** | 插件里不得出现 Player / Enemy / 遗物 / Boss |
| 2 | **依赖注入** | 需要外部对象时由调用方传入，插件内部不得去「找」 |
| 3 | **单一职责** | 一个插件只解决一个问题，粒度宁小勿大 |
| 4 | **配置驱动** | 所有可调参数进配置对象，禁止硬编码魔数 |
| 5 | **可卸载** | 必须提供 `destroy()`，卸载后不留残留（事件/定时器/节点） |
| 6 | **依赖只能向上，不能成环** | 「必需」才依赖，「可选」就注入 —— 详见 [依赖规则 v2](./依赖规则v2_前置模块与分层.md) |
| 7 | **每个插件自带** | README + 测试 + 可运行示例 |

**最简单的判据**：把这个插件的文件夹复制到另一个 Cocos 项目，需要改几行？
**答案是 0 才算合格。**

## 四、快速开始

### 4.1 引入

把需要的插件文件夹整个复制到你的项目 `assets/` 下即可（**记得连 `.meta` 一起复制**，
Cocos 靠 `.meta` 里的 uuid 追踪资源，只复制 `.ts` 会导致资源引用失效）。

### 4.1.1 ⚠️ 复制到 Cocos 项目后：记得抬高 `lib` 目标

本库大量使用 ES2016+ 内建方法（`Array.includes`、`Object.entries/fromEntries`、
`String.padStart/trimEnd` 等）。Cocos 生成的 `temp/tsconfig.cocos.json`
默认 `lib` 目标偏低，会导致**整库报上百条"属性不存在"**——
报错全在你没写过的代码上，很容易误判成"这个库有问题"。

在项目**根 `tsconfig.json`** 里显式抬高即可（不改本库任何源码）：

```json
{
  "compilerOptions": {
    "lib": ["ES2019", "ES2020", "DOM", "DOM.Iterable"]
  }
}
```

实测效果：104 项错误 → 3 项。

> ⚠️ **抬高 `lib` 只是让 TS 不再报错，不代表运行时一定有这些 API。**
>
> `lib` 管的是编译期可见性，`target` 管的是产物降级。
> 若目标平台（部分小游戏容器、老 WebView）实际不支持 `includes`，
> 会出现**编译通过、真机崩溃**。
>
> 所以正确做法是 **`lib` 与 `target` 一起抬**，或确认目标平台支持 ES2019。

### 4.1.2 ⚠️ 复制到 Cocos 项目后：`strict: false` 会让「判别联合」收窄失效

本库自带 `tsconfig.json` 是 `strict: true`，而 **Cocos 生成的 tsconfig 默认 `strict: false`**。
这会让一类代码在库里编译全绿、拷进项目后报错——即"判别联合"（discriminated union）：

```typescript
type R = { ok: true } | { ok: false; reason: 'too-few' | 'not-all-ready' };

const r = canStart();
if (r.ok) return null;      // ← strict:false 下**不收窄**
return r.reason;            // ← 报 TS2339: Property 'reason' does not exist
```

**根因**：布尔字面量判别式的收窄**依赖 `strictNullChecks`**。关闭后 TS 认为
`r` 仍可能是 `{ ok: true }`，于是访问只存在于失败分支的字段时报错。

实测（TypeScript 5.9.3）：

| 写法 | `strict:true` | `strict:false` |
|---|---|---|
| `if (r.ok) return null;` | ✅ 收窄 | ❌ 不收窄（TS2339 + TS2322） |
| `if (!('reason' in r)) return null;` | ✅ 收窄 | ✅ 收窄 |

**`in` 运算符收窄是结构判定，不依赖 `strictNullChecks`**，两种模式下都稳。

本库源码已全部改用 `in` 收窄（`matchmaking/Lobby.ts` 是最后一处，2026-09-06 修），
因此在默认配置的 Cocos 项目里应当零报错。若你自己的代码里用了本库返回的
`{ ok: true } | { ok: false; ... }`，**请照此写法**，不要依赖 `r.ok` 做收窄。

> 💡 **为什么不直接要求 `strict: true`？**
> 因为 rule7 的判据是"复制过去改 0 行"。要求使用方改配置，等于把成本转嫁给使用方。
> 库自己去适配目标环境才对。
>
> 若你确实切到了 `strict: true`，反而会暴露另一类问题：真实 Cocos 引擎的
> `EventTouch.getID()` 声明为 `number | null`，而本库自带的 `typings/cc.d.ts`
> 是最小桩、声明为 `number`。本库已对三处调用做了判空，两套声明下都能编译。
> 只抬一个的代价是"本地一切正常，上线白屏"。

### 4.2 一个完整例子：从摇杆到伤害

```typescript
import { JoystickCore } from './cocos-kit/joystick-mover/JoystickCore';
import { DamagePipeline } from './cocos-kit/damage-pipeline/DamagePipeline';
import { RNG } from './cocos-kit/rng/RNG';
import { EventBus } from './cocos-kit/event-bus/EventBus';

// 1. 事件总线（解耦战斗逻辑与 UI）
interface MyEvents { 'damage:dealt': { value: number; crit: boolean } }
const bus = new EventBus<MyEvents>();
bus.on('damage:dealt', (d) => floatingText.show(d.value, d.crit));

// 2. 摇杆（纯逻辑，可单测）
const joy = new JoystickCore({ radius: 80, deadZone: 0.15 });
joy.onDown(0, 100, 100);
joy.onMove(0, 150, 100);      // 向右推
const dir = joy.evaluate().dir;  // { x: 1, y: 0 }

// 3. 伤害管线
const dmg = DamagePipeline.createDefault();
const rng = new RNG(20240902);

// 4. 打一下（暴击由种子决定，全程可复现）
const result = dmg.apply(
  { raw: 20, type: 'fire', crit: rng.chance(0.25) },
  enemy                        // enemy 只需实现 IDamageable
);
bus.emit('damage:dealt', { value: result.value, crit: result.isCrit });
```

更多示例见 [`examples/`](./examples)。

| **Logger** | 分级日志 + 环形缓冲 | 崩溃时能导出最近 200 条——唯一的现场还原手段 |
| **Scheduler** ⭐ | 统一时间源 | **真暂停的唯一实现路径**；两条通道（游戏/UI）；顿帧一键 |

| **Seed** | 人类可读种子 | `12345 → 'IRON-33'`；`daily()` 按日期生成每日挑战种子 |
| **Modifier** | 数值修正框架 | `(base + Σadd) × (1 + Σmul)`；tag 批量清理 |
| **DamagePipeline** | 分阶段伤害计算 | 加机制 = 插 stage；护甲用**除法**公式；`stages` 可追踪中间值 |
| **Track** | 时间轴数据 | 区间查询（不漏事件）；`frameToTime()` 对齐美术标注的判定帧 |
| **Cooldown** | 冷却与充能 | 缩减用**除法**（乘法会导致 100% 缩减时无限放技能） |
| **SkillPlayer** | 时间轴播放器 | 时间源外部注入 → 暂停/慢动作自动生效；事件类型可注册扩展 |
| **JoystickMover** | 轮盘移动 | Core（纯逻辑）+ Mover（Cocos 薄层）分离 |

### 算法层（第五批，最易复用）

> 这一层**不认识你的游戏**，只认数字和坐标——换任何项目一行都不用改。

| 插件 | 一句话 | 关键设计 |
|---|---|---|
| **BinaryHeap** | 优先队列 | O(log n) 取最值；批量建堆是 O(n) 不是 O(n log n) |
| **LazyHeap** | 惰性删除堆 | A* 的 decrease-key：`remove` 是 O(1) 标记，`pop` 自动跳过 |
| **DisjointSet** | 并查集 | 路径压缩 + 按秩合并；**死图检测的核心** |
| **QuadTree** | 四叉树 | 范围查询；分裂时**不能重复计数** |
| **SpatialHash** | 空间哈希 | Cantor 配对支持负坐标；移动时自动清理旧格 |
| **AStar** | A* 寻路 | 支持地形代价、飞行单位；`closed` 存 stamp 不是布尔 |
| **PathSmoother** | 路径平滑 | 网格路径 58 步 → 21 步；对角线不擦墙角 |
| **FlowField** | 流场 | 多单位共用；构建一次，之后每单位 O(1) |
| **Shadowcasting** | 视野 + 战争迷雾 | **推荐**；墙本身可见（房间轮廓不会消失） |
| **Raycasting** | 射线视野 | 调试对照用；11×11 空房间只能看到 21/81 格 |
| **BSPDungeon** | BSP 地牢 | **死图率 0**（100 次实测）；沿树回溯连接天然连通 |
| **CellularDungeon** | 元胞洞穴 | **必须清孤岛**，否则宝箱可能生成在走不到的地方 |
| **MazeDungeon** | 迷宫 | 尺寸必须奇数；`braidRatio` 加环路（完美迷宫不好玩） |
| **Steering** | 转向行为 | 输出**力**不是速度；`arrive` 带减速（别用 `seek`） |
| **Flock** | 群体 boids | 分离/聚集/对齐三规则加权；带视野角度 |
| **Noise** | 程序化噪声 | 统一入口默认 Simplex；`heightMap` 默认归一化到 [0,1] |

### 战斗手感层（第六批，编排型）

> 这批**不做具体的事**，只负责把别的能力按正确时序串起来。
> 因为不做具体的事，所以零依赖——能力全靠注入。

| 插件 | 一句话 | 关键设计 |
|---|---|---|
| **SkillCaster** ★ | 技能释放编排器 | 不 import 任何插件；`origin` 决定判定中心；失败原因要给玩家看 |
| **Hitbox** | 判定形状与重叠 | 4 种形状；扇形参与的复杂组合是采样近似；offset 对查询方也生效 |
| **AttributeSet** | 属性容器 | 多个 mul **相加**不连乘（防收益爆炸）；条件修正会禁用缓存 |
| **Projectile** | 弹道系统 | 5 种运动模式；**要 sweep 不要 point**（防高速穿墙） |
| **Telegraph** | 攻击预警 | 三阶段；**active 后位置冻结**；低帧率用 while 防跳窗 |
| **SkillIndicator** | 技能指示器 | 只算参数不画；**与判定共用同一份 Shape** |
| **InputBuffer** | 输入缓冲 + 搓招 | **手感第一地基**；暂停必须传 dt=0；搓招允许中间有多余输入 |
| **CoyoteTimer** | 土狼时间 | 离地后仍可跳；消费后必须作废（防二段跳） |
| **DashController** | 冲刺 | 衰减曲线（非匀速）；末段减速**不能对位移打折**；`canCancel()` 取消后摇 |
| **CameraShake** | 震屏 | 多震源向量叠加；`strengthScale=0` 必须完全静止（可访问性） |

### 系统与深度层（第八批，公平性）

> 这批的 10 个模块有一个共同主题：**公平性**。
> 它们的失败模式也一致——**不抛异常**，
> 只是让游戏「感觉有点怪」，而开发者查不出来。

| 插件 | 一句话 | 关键设计 |
|---|---|---|
| **Perception** | 敌人感知（视觉/听觉/记忆/传播） | 同伴警报**延迟** 0.8s；声音「近场不打折」；抖动用 `Math.random` 不消耗 rng |
| **AttackToken** ★ | 攻击令牌，限制同时攻击数 | `holdTimeout` **必须设**；`remove()` 自动归还；`reset()` 先摘后通知 |
| **BulletPattern** | 弹幕发射器 + 序列编排 | 输出角度不是向量；`delay` = 第一发在 `delay + interval`；重置统一走 `_resetTime` |
| **ElementSystem** | 元素反应 | **反应定义里没有 `damage`**（效果在 `data`）；未知元素抛错不静默 |
| **TargetSelector** | 目标锁定 | 迟滞 + 粘性 + 宽限期；`byAngle` 最重要（否则锁身后的怪） |
| **ComboSystem** | 连招输入 | 前缀则等待、否则立即触发；`tick()` **必须每帧调用** |
| **ObjectiveSystem** | 关卡目标 | 5 种类型；`protect` 初始 = target（反向）；循环依赖构造时抛错 |
| **DifficultySystem** | 难度档位 + DDA | 幅度 ±15%、平滑、不显示；`allowDDA` 用 `=== false` 判断 |
| **GachaPity** | 抽卡保底 | 跨抽累计（区别于 PRD）；软保底；50/50；十连保底 |
| **ScoringSystem** | 战斗评分评级 | `direction` 显式声明；par/zero 写反**构造即抛错**；`missingAs: 'skip'` |

## 六、必踩的坑（按危险程度排序）

| 坑 | 后果 | 解法 |
|---|---|---|
| 混用 `Math.random` | 种子复现失效 | 用 lint 规则禁用 `Math.random` |
| 用 `setTimeout` 做计时 | **暂停时 buff 仍在倒计时** | 所有计时统一走注入的 `tick(dt)` |
| 对象池取出不 reset | 新对象带着旧状态 | `onGet` 钩子强制重置 |
| 摇杆输出不归一化 | **斜向移动快 1.41 倍** | `normalizeOutput: true` |
| 护甲用减法公式 | 负伤害 / 完全免疫 | `dmg × 100/(100+armor)` |
| 冷却缩减用乘法 | 100% 缩减 → 无限放技能 | `cd ÷ (1 + 缩减)` |
| 判定与动画差 3 帧 | 玩家觉得「打空了」 | `Track.frameToTime()` 对齐美术标注 |
| 系统用 `setTimeout` 计时 | **暂停时 buff 仍在倒计时** | 所有计时走 `Scheduler` |
| A* 不检查 `found` | 终点不可达时 `path[0]` 是 undefined | **每次都要判 `if (!r.found) return`** |
| 地牢生成后不自检 | 玩家走进死图 / 宝箱拿不到 | `isFullyConnected()` + 10000 次批量自检 |
| 用 `seek` 做到达 | 单位冲过目标再折返，**抖动** | 用 `arrive`（减速半径内线性衰减） |
| 撞墙只反向速度 | 单位卡在墙里反复横跳 | **先回退位置**，再处理速度 |
| `heightMap` 关掉归一化 | 阈值判断失效，地形忽大忽小 | 保持默认 `normalize: true` |
| 手写八分体坐标变换 | 视野从圆形变菱形，**看起来还挺合理** | 抄标准 2×2 矩阵，靠测试验证 |
| 暂停菜单走缩放通道 | 菜单自己被暂停，淡不进来 | 用 `everyFrameUnscaled` |
| 忘了 `endFrame()` | 按一次攻击连放好几次 | InputManager 帧末必须调用 |
| `setAxisAnalog` 在 `beginFrame` 前 | 手柄摇杆完全没反应 | 顺序：beginFrame → setAxisAnalog |
| 顿帧用缩放时间计时 | 80ms 顿帧变成 1.6 秒卡顿 | TimeScale 的到期判定走真实时间 |
| 不 clamp realDt | 切后台回来角色瞬移穿墙 | Scheduler 默认 clamp 到 0.1s |
| 配置校验遇到错误就停 | 改一个重启一次 | Validator 一次报全 |
| Cocos 组件忘记 `off` | 切场景后报 null | `onDestroy` 里成对 `off` |
| 只复制 `.ts` 不复制 `.meta` | 资源引用全失效 | 导入工具必须连 `.meta` 一起复制 |
| **指示器/预警/判定各写一份参数** | 「看着能躲开却被打中」，极难排查 | 三处**共用同一份 `Shape`** |
| **预警进入 active 后位置跟着施法者** | 玩家躲开了判定圈还跟着他 | **active 开始时冻结位置** |
| `origin` 用错（近战用了 aim） | 扇形技能全部打空 | 近战用 `caster`（默认），落点 AOE 用 `aim` |
| 判定写在阶段推进之后 | `hitDelay: 0` 的技能**永远打不中** | 判定必须在推进阶段**之前** |
| 高速弹丸用点检测 | 偶尔穿墙，无法复现 | 接口要 `sweep`；或调小 `maxStep` |
| 冲刺末段对位移打折 | 位移先超调再回缩，终点抖一下 | 让衰减指数平滑增大（保证 ds/du > 0） |
| 震屏偏移了输入/瞄准 | 玩家觉得「往左推它往右走」 | 只偏相机节点，输入与 UI 不跟着偏 |
| 震屏用缩放后的 dt | 顿帧时震屏变缓慢漂移，失去冲击力 | 用**未缩放**时间 |
| 输入缓冲在暂停时继续老化 | 恢复后输入已失效 | 暂停传 `dt = 0`，或注入 `now` 时间源 |
| **AttackToken 不设 `holdTimeout`** | 动画卡死 → **所有敌人永久失去攻击能力**，不报错 | 设为「最长攻击动画 × 2」 |
| 死亡时不调 `remove()` | 令牌永久少一个，无任何报错 | 实体销毁时统一调 `remove()` |
| **声音衰减用线性** | 中距离枪声永远 < 1.0 → 开枪引不来敌人 | 近场不打折 + 二次滚降 |
| 感知只发 `spotted` 不发 `suspicious` | 敌人「毫无征兆地突然冲过来」 | 视觉路径也要在阈值处发一次 |
| **Gacha 判定写 `n + 1 >= hardPity`** | 硬保底提前一抽触发，承诺对不上 | `pityCount` 已含本次，直接比较 |
| `worstDry` 统计口径不一致 | 报出「四星 23 抽没出」这种假故障 | 语义是「连续多少抽没拿到 r **及以上**」 |
| **Scoring 的 par/zero 方向写反** | 「打得越快分越低」，查不出原因 | 构造时抛错，不静默兜底 |
| Scoring 用 `missingAs: 'zero'` | 缺指标的关卡天然低分，玩家困惑 | 用 `'skip'`，按实际权重归一化 |
| **Targeting 的 `update()` 传 dt=0** | 宽限期永不耗尽，目标消失了还锁着 | 传真实 dt |
| Targeting 少了 `byAngle` | 玩家锁到身后的怪，角色突然回头 | 必加 `byAngle` |
| **Combo 忘记 `tick()`** | 输入永远挂着 → 「过一会儿自己出招」 | 每帧调用 |
| Objective 忘记先 `tick()` | 目标是 `inactive`，进度加了没反应 | 构造后先 tick 一次 |
| **`allowDDA` 用 `!x` 判断** | 所有没配该字段的档位全部失去 DDA | 用 `=== false`（opt-out 布尔陷阱） |
| DDA 幅度 > 20% | 玩家察觉「难度在乱跳」，成就感崩塌 | 钳制在 ±15% 且默认不显示 |
| `restartEmitter()` 忽略 delay | 同一招式时快时慢 | 重置逻辑收敛到 `_resetTime()` |
| 弹幕用 `if` 不用 `while` | 掉帧后弹幕缺一段 | 用 `while` + guard |
| **预警音不设最高优先级** | 通道被爆炸音占满 → 预警音静默丢弃，玩家死得莫名其妙 | `PRIORITY.CRITICAL`，抢占低优先级 |
| 音效去重窗口设太大 | 连续命中只响一次，打击感变弱 | 50~80ms，别设到 200ms |
| BGM 用 `linear` 曲线 | 过渡中间音量变轻一下，听感廉价 | 用默认的 `equal-power` |
| **每帧调 `setState(同一状态)`** | 过渡被反复重启，音量卡在 0 | 同状态返回 false，不重启 |
| **`skip()` 写成 `stop()`** | 跳过后镜头停在半路，玩家看到很怪的中间画面 | skip = 快进到结尾并应用终态 |
| **seek 只应用当前 step** | 之前的 step 效果全丢，镜头没移动 | 必须重放 `start <= t` 的所有 step |
| `waitFor` 不配 `timeoutMs` | 玩家不按 → 演出永久卡住 | 默认 30s 兜底，必须可配 |
| **转场时 `overlay=0` 不隐藏节点** | 全屏遮罩吃掉触摸 →「转场后点不动了」 | 用 `overlayStyle()` 的 `visible` |
| 转场不设 `loadTimeoutMs` | 加载卡死 → 永久黑屏，玩家以为崩了 | 默认 30s，超时进 failed 而非继续 |
| 转场失败后永久锁输入 | 游戏没崩但什么都不响应 | 锁输入的同时**必须**给重试/退回入口 |
| **小地图旋转后又翻一次 Y** | 正前方显示在右边，整张图转了 90° | 旋转分支里一次性完成翻转 |
| 圆形小地图分别 clamp x/y | 图标跑到圆外的四个角上 | 等比例缩放到半径 |
| 迷雾分辨率对齐小地图像素 | 200×200 白白浪费内存 | 取 32~128，渲染时放大插值 |
| **建造先扣资源再放置** | 失败时资源凭空消失，玩家认为你在偷东西 | 验证 → 占位 → 扣资源 |
| 拆除未完成建筑只退 50% | 玩家不敢再尝试建造 | 未完成取消 100% 返还 |
| **升级做成"拆了重建"** | 位置被抢、净亏 50%、id 变了引用全断 | 原地替换，保留 id 与位置 |
| **自动画质用均值判帧率** | 一次 GC 停顿就降级，画面无谓变差 | 用**中位数** |
| 升降级阈值相同 | 边界反复横跳，画面一直在闪 | 升级阈值至少高 8fps |
| **冷却期内直接读 fps** | 显示「已降到低画质，但帧率 60」 | 先判 `state.fpsValid` |
| 手动设画质后不锁自动 | 玩家的设置被系统改回去，反复调然后生气 | `setManualLevel()` 会锁定 |
| **脱敏在对象上做** | `Error.stack` 里的手机号漏掉 | 在**序列化之后**的整个文本上做 |
| 自定义脱敏规则漏 `g` 标志 | 只替换第一个，第二个手机号泄露 | 正则务必带 `g` |
| 诊断收集自己抛错 | 玩家「点发送 → 崩溃 → 再点 → 再崩」 | 分区独立 try/catch |

## 八、测试

纯逻辑层（不碰引擎）可以脱离 Cocos 直接单测：

```bash
npm i -D jest ts-jest @types/jest

```

建议的测试重点（按性价比排序）：

1. **RNG**：同种子必须产生完全相同序列（这是可复现的核心承诺）
2. **DamagePipeline**：每个阶段单独验证 + 中间值正确
3. **Modifier**：运算顺序、tag 清理、缓存失效
4. **Track**：序列化往返无损、区间查询不漏事件
5. **JoystickCore**：死区、归一化、多点触摸、松开归零

UI / 渲染相关（JoystickMover 的 Cocos 部分）以手动验证为主——
自动化 UI 测试的成本收益极差，不要追求 100% 覆盖率。
