## 总审再审标准（我会据此判"采纳 / 驳回 / 升降级"）

### 采纳的硬门槛

一条问题要被采纳，**三件套缺一不可**：

1. **行号**：精确到 `<文件>:<起止行>`
2. **证据**：实测输出，或可验证的推导链。**"应该""可能""似乎"一律打回**
3. **后果**：什么场景下暴露、表现为什么症状。**说不出后果的问题不成立**——
   通常意味着它不是真问题，或作者没想清楚

### 严重度口径

| 档 | 判据 | 处理 |
|---|---|---|
| **P0** | 产生错误结果 / 崩溃 / 泄漏，且**静默**（不报错） | 必须修 |
| **P1** | 边界条件错误、契约不一致（注释说谎）、O(n²) 退化 | 应该修 |
| **P2** | 可读性、冗余、文档瑕疵 | 可选，视返工成本 |

> 我掌握全库视角，**跨批次的影响面由我裁决**——同一类问题在不同批次出现时，
> 严重度可能上调（说明是系统性模式）或下调（说明是孤立个案）。

### 常见驳回理由（提前说清，减少返工）

- **证据不足**：只有推理没有实测。→ 写个最小复现脚本跑一遍
- **这其实是设计意图**：本库大量"看起来像 bug"的写法都带长注释解释原因。
  **没读注释就报问题，是最高频的驳回原因**
- **后果不成立**：理论上存在但触发路径不存在（如内部私有方法、参数已在上游夹紧）
- **重复劳动**：报了第 2 节里已审结的地基单元或已知全局问题
- **改了不该改的**：本轮只审不改；以及"顺手重构"一律驳回（超出精审范围）

### 关于"注释说谎"这类问题

本库已发现 2 例 **README 把 bug 记录成标准行为**（`smoothDamp` 的 maxSpeed、
以及一份"修正自引擎实测报告"但实际参数位置写错的数据）。
所以对文档类问题我会从严：

- 文档与实现不一致 → **默认判 P1**，因为"写错的文档比没文档更糟"
- 文档把缺陷记为设计意图 → **默认判 P0**，因为它会阻止下一个人修复

## 全局议题裁决（**已全部结案**）

- [x] ~~**矩形坐标系口径**~~ **已裁决（第六批）**：注释原文自相矛盾——
      `IRect` 写"左下+右上"，`IRectSized` 写"左上角+宽高"，
      而 `toCorners` 把 `IRectSized.y` 直接当 `minY`。
      两句话放一起必然有一个坐标系下是错的（y 向上时"左上角"的 y 应是 maxY）。
      **统一口径**：`min/max` 是轴无关的数值大小；`IRectSized` 的 x/y 是 **min 角**；
      `toCorners` **假设 y 向下**。已更正 `_core/types.ts` 注释，
      并用 `tests/run_phase6.ts` 固化行为（改了会失败）。
- [x] ~~**相切语义**~~ **已裁决（第六批）：两者都保留，不统一**。
      实测 `ds.rectsOverlap` 相切→false（`<`），`_core.rectOverlaps` 相切→true（`<=`）。
      这不是笔误：半开/不含相切是**空间索引**的正确语义
      （避免边界物体被两个节点重复命中）；闭区间/含相切是**通用 AABB** 的常规约定。
      强行选一个，必然有另一个场景出 bug。
      已给两侧补注释说明适用场景，并用测试**给"差异本身"上锁**——
      有人想对齐风格改成一致时，`run_phase6.ts` 会失败。
      同理 `ds.pointInRect`（半开）vs `_core.rectContains`（闭区间）也保留差异。
- [x] ~~**平行实现合并**~~ **已裁决：保留两套，文档已说明选型**。
      `pathfinding/README.md`、`spatial/README.md` 各自开头都有"与 XX 怎么选"对照表。
      `spatial` 明确记录：保留两个是因为 API 差异大，
      强行合并会破坏 `examples/batch3-usage.ts` 的依赖。
      既然选型文档已就位且测试都通过，合并的收益低于破坏成本 → 维持现状。

## 验收五条硬标准

1. **是否真的复现过** —— 要运行输出，不要"理论上会……"
2. **测试是否真的会失败** —— 问："回退修复后这条断言还成立吗？"成立就是无效用例
3. **有没有对照用例** —— 防矫枉过正（真实反例：`maxVoices` 夹成 `[1,512]` 把合法的 0 也夹了）
4. **有没有顺手重构** —— 改动是否超出必要范围
5. **有没有把"设计如此"误判成 bug** —— 本项目最易复发的一类（相切语义、display 单位元、prewarm 契约）

详见 `archive/round02/review_A.md` / `review_B.md` 第 2 节。
