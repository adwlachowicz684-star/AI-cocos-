## 5. 需要知会的三点（非阻塞）

### 5.1 `_kitmeta.json` 的 `achievement → _core` 仍未登记

W7-B 报告 §7.2 提到它用 `check-deps.js --fix` 写过一次登记，随后被并发推送冲掉、又修了一次。
**我验收时（当前 main）再跑一次 `check-deps.js`，仍然是未登记：**

```
[5] 登记与源码一致性
  ✗ import 了但没登记 8 条：
      i18n / blessing / curse / rarity / achievement / rebind / gameflow / accessibility → _core
```

其中 `achievement` 属 W7-B。这不是 W7-B 的疏漏——
`_kitmeta.json` 是全库共享登记文件，不在任何窗口的单元边界内，
谁基于旧树推谁就会盖掉别人的。

**建议（与 W7-B 一致）：合并期结束前由总审统一跑一次 `--fix`**，别再让各窗口分别写。
我作为验收方不越界代改。

### 5.2 `unlock()` 默认校验前置是对外行为变更

修复前 `unlock('B')` 在前置未达成时返回 `true`，现在返回 `false`。
这是任务书要求修的，方向正确；但它会**静默改变既有调用方的行为**——
任何"先解锁后补前置"的既有代码（补发脚本、GM 工具、老存档迁移）现在会静默失败。

实测基线 3696 项里没有用例依赖旧行为，所以库内无影响；
但**下游项目**可能依赖。建议在 README 或变更说明里显式点一句，
并提示改用 `unlock(id, true)`。

### 5.3 `setExpressionWarningHandler` 是模块级全局

`_warnHandler` 是模块级变量，不是实例级。
多个 `Expression` 实例共享同一个 handler，且告警去重靠实例自己的 `_warned`
（每个实例一份），所以"同名问题只报一次"是**按实例**计的，不是全局。

当前设计没问题（handler 本来就该是宿主全局装一个），
只是"每个表达式每个键只报一次"这句注释容易被读成"全局只报一次"。
如果将来有高频创建 Expression 的场景（每帧 new），去重会失效、日志会刷屏——
那时可能需要改成按表达式源码去重。
