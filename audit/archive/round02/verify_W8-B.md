## 七、我认领一处错误：Lo8 的归因是我错了

我第 1 版实测 `add x,y → draw → add z → draw,draw` 得到 `{"first":"y","second":"z","third":"y"}`，
据此判断"**y 在一轮内出现了两次，违反 README 承诺的『一轮之内每个元素恰好出现一次』**"。

**这个归因是错的。** W8-A 指出 `add()` 本身就是轮次边界。我在最新代码上复核：

```
add x,y 后 remaining = 0
draw#1 = x | remaining = 1
add z 后 remaining = 0        ← add 触发重洗，进入新一轮
add 之后连抽 3 次 = ["z","y","x"] | 去重数量 = 3   ← 新一轮内仍然恰好一次
```

跨过 `add` 这条边界看到重复是**正常的**——README 说的是"**一轮之内**"，
而 `add` 之后已经换了一轮。**我把跨轮的重复当成了轮内的重复。**

正确定性是 W8-A 给的：**"README 没说明这个边界"**，不是"README 被违反"。
两者修法完全不同：前者补文档，后者要改 `add()` 的实现。
按我的错判去"修"，会去动一个根本没坏的性质。

记在这里是因为——这正是我在第 1 版报告里专门提醒对方"重点看这类"的错误，
**我自己在这份文档的上一版里犯了一次**。
