## 四、建议补（3 处，不阻塞）

### 1. W4A-02：给那条"对照"用例改个名字（或加注释）

`run_phase10_w4a.ts:166`「对照：interval = 0 / 负数 / 非数字都仍被拒」在修复前**会失败**
（它拦的是 `interval: 'x'` 这类非数字类型的加固）。
上一版只发现这 1 条；本轮实测发现 `difficulty` 那条 `对照：destroy() 不动难度档配置`
同样在修复前失败（原因是 `d.destroy is not a function`）。

两条用例本身都**是对的**，只是"对照"这个名字会让人误判它的性质。
建议在用例名或注释里点明"含非数字类型的加固"／"依赖新增的 destroy()"。

### 2. W4A-10③：`SequencePlayer` 的循环次数，报告与测试注释都写错了

`result_W4-A.md` 写"跑 10.2 秒只触发 **9** 次"；
而同一份测试文件里两处注释**自相矛盾**：

```
run_phase10_w4a.ts:687  "实测（修复前）：dt=0.3s、周期 1s，10.2 秒只触发 9 次（理想 10 次）"
run_phase10_w4a.ts:701  "10.2 秒 ÷ 1 秒周期 = 10 次。修复前（_time = 0 丢弃余量）只有 8 次。"
```

本窗口实测：**修复前是 8 次**（701 行那句才是对的，687 行与报告沿用了错的那个）。

不影响修复正确性（修复后确实是 10 次），但按本库"文档与实现不一致默认 P1"的口径，
**同一文件内两处注释互相打架**是应该修掉的——下一个人读到 687 行会以为是 9，
然后怀疑自己的测量。建议把 687 行与报告统一改成 8。

### 3. W4A-14：非 override 分支对危险键是"静默跳过"

`addLocale` 改成逐键写入后，`if (!isSafeKey(k)) continue;` 会**静默丢弃** `__proto__` 等危险键。
语义上是对的（语言包合并场景下，跳过比抛错安全），但"静默"与本库
"宁可立即失败并说清为什么"的 guard 口径有张力。

建议补一句注释说明"这里刻意静默跳过而不是抛错，因为语言包常来自外部文本，
一个坏 key 不该让整个语言包加载失败"——把"为什么可以静默"写下来，
否则会被下一个人当成同类缺陷重提。

## 六、提请总审留意（2 处）

### 留意 1 · W4A-08 的 `has()` 语义变更 —— 代价比上一版评估的更小

上一版我提过"有 fallback 时 `has()` 恒为 true，会导致'这份 en-US 还差几条'这类用法失效"。

本轮实测**修正了这个判断**：

```
修复前：has("ui.start")   = false   t() = "开始"     ← 缺陷
修复后：has("ui.start")   = true    t() = "开始"

修复前：coverage("en") = { total:3, translated:0, missing:[ui.start, item_one, item_other] }
修复后：coverage("en") = { total:3, translated:0, missing:[ui.start, item_one, item_other] }
```

**`coverage()` 是按指定语言包独立统计的，不受 `has()` 变更影响。**
也就是说"这份语言包还差几条"这个需求**本来就不该用 `has()` 做**，`coverage()` 完整接住了它。
真正的代价只落在"有人误用 `has()` 做覆盖率自检"这一个窄场景上，风险低于上一版评估。

W4-A 已在 `i18n/README.md` 写明新口径，**无需返工**。

### 留意 2 · W4A-15 的抛错是 breaking change，但 README 给的规避办法不可用

W4-A 在 `matchmaking/README.md` 加了说明，方向对；但给的建议有问题：

> "撮合侧要在开赛前用 `validateTeamAssignment` 之类的校验拦住这种组队组合"

**`validateTeamAssignment(teams)` 的入参是"已分好的队伍"，是事后校验**
（`TeamBalancer.ts:518`）。开赛前还没有 teams，调不了它，也就无法"预判无解"。

可行的规避是：① `try/catch` 包住 `balanceTeams`；
② 进队时校验组队规模组合能否被 `teamCount` 整除装箱。
建议总审在合并时把 README 那句改成这两条之一——**不阻塞本条验收**，
因为改的是一句指引，不是实现。
